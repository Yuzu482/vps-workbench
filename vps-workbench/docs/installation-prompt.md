# 交给模型的 VPS Workbench 安装提示词

复制下方整段，交给一位能访问你的 Windows 主机且有适当权限的助手。把能确定的占位内容替换掉。密码、私钥、API Key、登录码和 Cookie 都在对应安全入口处理。

```text
请协助我安装和验收 VPS Workbench。请先检查实际环境和发行文件，再按已授权范围执行。

发行地址：https://github.com/Yuzu482/vps-workbench/releases
指定版本：[填写版本；默认使用我确认的具体 Release]
执行模式：[仅本机 SDK / 仅 VPS SSH / 两者]
所需执行端：[Codex / Claude Agent SDK / Claude CLI / Antigravity ACP]
Windows 安装目录：[新目录，或由你建议后确认]
VPS 主机别名与 SSH 用户：[仅填写非秘密信息；仅 VPS 路线需要]
VPS 项目目录：[用户拥有的绝对路径]
预期 VPS 出口：[由我通过可信渠道提供]
安装授权：[说明已授权的下载、解压、依赖安装和远端变更范围]
真实模型试跑授权：[默认未授权]

1. 打开我指定的 Release，读取 DEPLOYMENT.md，并用 SHA256SUMS.txt 校验 Windows ZIP 和实际使用的 Linux 后端包。记录版本、提交和哈希。仓库需要访问权限时让我通过 GitHub 自己登录。
2. 检查 Windows x64、可用磁盘和现有版本。VPS SSH 路线另外检查 .NET 10 Runtime、Windows OpenSSH 客户端及 Python 3.11。把 Windows ZIP 解压到新目录，先设置独立的 VPS_WORKBENCH_DATA_DIR 启动试用。保留原程序和数据。
3. 本机路线只安装我选中的按需运行时，登记获准的只读工作目录，账号通过应用的安全入口或官方 CLI 登录。需要我输入凭据时，明确指出窗口并等待我操作，保持凭据留在该环境。
4. VPS 路线先使用已有 SSH 配置或等我提供配置。通过可信控制台或已有记录核对主机指纹。用普通 SSH 用户检查系统、架构、项目目录和预期出口。工作台向导可用时，按“测试连接 → 安装所选执行端 → 重新检查账号和模型目录”推进。手动部署时先校验并解压后端包，再执行 verify、doctor 和已授权的 install。
5. 保留已有账号、配置和会话。服务器依赖需要提权、云防火墙需要调整、主机指纹变动、需要迁移或替换现用版时，先说明具体变化并等我授权。SSH 放行只针对我指定的来源。阶段失败时保留原回执并查询它。
6. 保持执行位置分离：本机账号和请求走本机；VPS 账号和模型请求走 VPS。只有我明确批准后才执行真实模型试跑。批准后每条路线用一轮短对话和一次追问验收响应与续聊，再核对停止、重启后历史和网络证据。区分 SSH 连通、VPS 预检观测的出口和服务实际看到的 IP。
7. 汇报安装路径、版本、校验结果、每条已验证路线及仍待验证的项目。列出原程序与数据的位置和回滚步骤。保留现用版本，除非我明确授权切换。
```
